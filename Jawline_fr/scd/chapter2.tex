\section{System Use Case Modeling}

A use case defines a set of use-case instances where each instance is a sequence
of actions a system performs that yields an observable result of value to a
particular actor. The MazdoorLink system follows a \textbf{Serverless
Client-Side Architecture} in which a Flutter frontend communicates directly
with Firebase services (Authentication, Firestore) and external APIs
(Cloudinary, Google Maps) without a dedicated application server. The following
29 use cases are modelled below.
Figure~\ref{fig:usecase} presents the complete use case diagram showing all
major actors and their associated system functions.

integrations (Firebase Authentication, Cloudinary, Google Maps Platform) that
